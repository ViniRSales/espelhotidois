# Requisitos

## Requisitos funcionais

| ID | Descrição |
|---|---|
| RF01 | O doador deve poder cadastrar uma doação com foto, descrição e categoria |
| RF02 | O receptor deve poder cadastrar uma solicitação com poucos campos obrigatórios |
| RF03 | Instituições devem poder se cadastrar como receptores verificados |
| RF04 | O sistema deve sugerir automaticamente combinações (match) entre doações e solicitações |
| RF05 | O receptor deve ser notificado quando surgir uma doação compatível |
| RF06 | O usuário deve poder filtrar doações por categoria, localização e urgência |
| RF07 | Doador e receptor devem poder conversar diretamente pela plataforma |
| RF08 | O contato entre doador e receptor deve permitir mensagens de áudio, além de texto |
| RF09 | Doador e receptor devem poder agendar data e horário da retirada ou entrega |
| RF10 | O sistema deve oferecer a opção de retirada em domicílio para itens de grande porte |
| RF11 | O status da doação deve ficar visível (disponível, reservada, a caminho, entregue) |
| RF12 | Instituições parceiras confiáveis devem exibir um selo de verificação |
| RF13 | O sistema não deve exigir comprovações excessivas do receptor |
| RF14 | Doadores e receptores devem poder se avaliar após a doação |
| RF15 | Necessidades urgentes devem aparecer em destaque |

## Requisitos não funcionais

| ID | Descrição |
|---|---|
| RNF01 | A aplicação deve ser responsiva, funcionando em celular e computador |
| RNF02 | A interface deve ser simples, com poucos cliques, adequada a usuários com pouca familiaridade com tecnologia |
| RNF03 | Os dados dos receptores não devem ser expostos publicamente |
| RNF04 | O sistema deve estar disponível 24 horas por dia, 7 dias por semana |
| RNF05 | O front-end deve ser desenvolvido em React e o back-end em Spring Boot |
| RNF06 | O código deve ser publicado em repositório público no GitHub |
| RNF07 | Busca, match e notificação devem responder em até 3 segundos |
| RNF08 | A comunicação da plataforma deve ter tom acolhedor e sem julgamento |
